- The module is organized into functional sub-packages: `routing` (load-balanced gateway with failover), `resilience` (circuit breaker, retry executor, backoff strategy), `rate` (token bucket and multi-bucket rate limiters), `reconnect` (exponential backoff reconnect manager with storm protection), `auth` (token state persistence abstraction), `depth` (order book engine with event-driven updates), `chaos` (fault injection scenarios), `startup` (lifecycle management and preflight validation), and `observability` (decorator wrappers for metrics).
- Central entry point is `LoadBalancedBrokerGateway`, which implements `IBrokerConnection` and aggregates multiple broker connections behind a single facade, delegating market data to `LoadBalancedMarketDataProvider` and orders to `FailoverOrderCommand`.
- Dependency direction flows from high-level facades (`LoadBalancedBrokerGateway`) down to low-level resilience primitives (`CircuitBreaker`, `TokenBucketRateLimiter`), with all components depending on the `broker-api` module's port interfaces (`MarketDataProvider`, `OrderCommand`, `WebSocketMultiplexer`).
- Build manifest (`build.gradle`) declares `api` dependencies on `:broker-api` and `:core`, confirming this module bridges the broker adapter API with core domain models.
