- Entry point is `BrokerCertification.runFull()`, which orchestrates nine category-specific check groups (market-data, options, portfolio, orders, advanced-orders, margin, futures, capabilities, instrument-catalog) and aggregates results into a `CertificationReport`.
- Core domain model uses immutable records: `CertificationCheck` (single check result with status/evidence/latency), `CertificationStatus` enum (PASS/FAIL/PARTIAL/SKIP), `CertificationReport` (aggregated report with overall status and latency summaries), and `CertificationArtifact` (persistable snapshot of a check).
- Persistence layer is `CertificationArtifactStore`, which serializes artifacts as JSON under `CertificationArtifacts/<broker>/<category>/<check>.json` using Jackson ObjectMapper with indented output and ISO date formatting; it also provides lookup by broker/check-name and artifact counting.
- Each check wraps a lambda (`CheckRunner` functional interface) in `runCheck()`, which adds a 200ms delay before execution and catches exceptions to produce PASS/FAIL outcomes with evidence or error messages.
- Capability checks use `broker.supports(Class<?>)` to detect optional broker features (bracket orders, GTT, slice orders, session-risk, news, kill-switch, websocket) without failing the certification — unsupported capabilities are recorded as PASS with "not supported (optional)" evidence.
