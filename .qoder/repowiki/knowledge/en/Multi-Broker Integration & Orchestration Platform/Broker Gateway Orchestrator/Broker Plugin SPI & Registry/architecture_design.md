- Core SPI interfaces: `BrokerProvider` (plugin contract), `BrokerRegistry` (lookup abstraction), `BrokerExtras` (escape hatch for broker-specific features), and `BrokerHealthCheck` (lightweight connectivity verification).
- Two registry implementations: `ServiceLoaderBrokerRegistry` delegates to `DefaultBrokerRegistry` for one-shot startup discovery via `java.util.ServiceLoader`; `BrokerPluginRegistry` is a hot-reloadable, thread-safe registry using `ConcurrentHashMap` with a `PluginListener` observer pattern for runtime registration/deregistration events.
- Each broker provider (`DhanBrokerProvider`, `IciciBrokerProvider`, `UpstoxBrokerProvider`) implements `BrokerProvider`, declares capabilities via `BrokerDescriptor` (a record with capability maps, supported segments, rate limits, and per-capability `CapabilityMetadata`), and bridges to `BrokerComposition` to create `IBrokerConnection` instances.
- Broker-specific extras (`DhanExtras`, `IciciExtras`, `UpstoxExtras`) implement `BrokerExtras` with an `invoke(String, Object...)` dispatch pattern exposing optional port capabilities; health checks (`DhanHealthCheck`, etc.) implement `BrokerHealthCheck` by performing lightweight LTP or auth probes.
- Dependency direction: SPI interfaces in `com.tradej.brokergateway.spi` are leaf contracts; impl subpackage depends on both the SPI and external modules (`broker-api`, `composition`, `core`).
