- **Capability-Based SPI**: The `broker/api` module defines the `IBrokerConnection` interface, which exposes optional trading capabilities (e.g., `MarketDataProvider`, `OrderCommand`) via a generic `getCapability` method, allowing diverse brokers to expose only supported features.
- **Plugin Discovery**: The `broker-gateway` module uses Java's `ServiceLoader` mechanism to discover `BrokerProvider` implementations from vendor-specific modules (`dhan`, `icici`, `upstox`), decoupling the core gateway from concrete vendor logic.
- **Resilience Layer**: The `broker/core` module provides cross-cutting resilience patterns—including circuit breakers, rate limiters, and load-balanced routing—that wrap vendor connections to ensure stable connectivity regardless of individual broker reliability.
- **Unified Access**: The `BrokerGateway` acts as the facade, aggregating discovered plugins into a single entry point that returns `BrokerHandle` instances, abstracting the underlying vendor-specific connection details from the client.
