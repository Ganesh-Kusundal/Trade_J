- Core API layer: `NodeExecutor` interface defines the execution contract (`descriptor()`, `execute(NodeContext, config)`), paired with immutable records `NodeDescriptor`, `NodeContext`, `NodeResult`, and `PortDescriptor` as the foundational data model.
- Adapter sub-package (`adapter/NodeAdapterFactory`): bridges legacy `BasePipelineNode` implementations into the `NodeExecutor` contract via an internal `AdaptedNodeExecutor`, translating between `PipelineContext` and `NodeContext` and collecting `DomainEvent` outputs.
- Concrete node implementations are organized by functional domain in sub-packages (`data/`, `feature/`, `scanner/`, `output/`), each implementing `NodeExecutor` and declaring typed input/output ports via `PortDescriptor`.
- Dependency direction flows inward: concrete nodes depend only on the core API types; the adapter depends on both the core API and external pipeline runtime (`trade-pipeline-platform`) plus domain event infrastructure (`core`).
- Build manifest (`build.gradle`) declares dependencies on `:core`, `:data-historical-ingest`, and `:trade-pipeline-platform`, confirming the module's role as a thin abstraction layer over existing pipeline and domain infrastructure.
