- The `composition` package acts as a manual dependency-injection layer: `FullComposition` aggregates `BrokerComposition`, `DataComposition`, and `ExecutionComposition` via static factory methods (`create`, `createFull`) without Spring annotations. Each sub-composition encapsulates its own wiring logic (e.g., `BrokerComposition` selects broker adapters via switch on `BrokerType`; `DataComposition` constructs Chronicle/DuckDB stores from `StorageProfile`).
- The `nodes/trade-node-library` defines a portable node-execution contract: `NodeExecutor` interface with `descriptor()` and `execute(NodeContext, Map)`; `NodeDescriptor` record for self-describing metadata; `NodeResult` record for uniform output. `NodeAdapterFactory` bridges legacy `BasePipelineNode` instances into the `NodeExecutor` contract.
- The `architecture-test` module enforces cross-cutting constraints using ArchUnit: Spring-free core modules, strict module boundary rules (core must not depend on outer modules), and mandatory design patterns (Command, Chain of Responsibility, State, Strategy, Specification, Adapter). Tests run under the `architecture` JUnit tag via a custom `architectureTest` Gradle task that aggregates compiled classes from all scanned modules.
