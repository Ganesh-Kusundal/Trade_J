- **Dual-Storage Strategy**: Uses Chronicle Queue for high-throughput, append-only Write-Ahead Logs (WAL) and event sourcing (e.g., `ChronicleEventWal`, `EventSourcedOrderRepository`), and DuckDB for analytical querying of market data and trade lifecycles (`DuckDbEventStore`, `DuckDbScanStore`).
- **Replay Engine**: Includes a dedicated `replay` package (`ReplayRunner`, `HistoricalEventReplayService`) that leverages Chronicle Queue tailers to replay historical events into the system, supporting virtual clock synchronization for deterministic testing and backtesting.
- **Connection Management**: Implements a thread-safe `DuckDbConnectionPool` that serializes writes via `ReentrantLock` while allowing concurrent read-only connections, optimizing for DuckDB's single-writer architecture.
- **Interface Implementation**: Concrete stores implement core domain ports like `DomainEventHandler` and `EventWriteAheadLog`, ensuring persistence logic is decoupled from business logic in the `core` module.
