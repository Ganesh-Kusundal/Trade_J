- **Transport abstraction layer**: `WebSocketTransport` interface decouples routing logic from Spring's `WebSocketSession`, enabling testability and framework independence (`transport/WebSocketTransport.java`).
- **Topic-based router with async dispatch**: `GatewayTopicRouter` maintains bidirectional topic↔transport mappings and uses a bounded `ArrayBlockingQueue` (default capacity 1024) with a dedicated background publisher thread for non-blocking event delivery, dropping events under backpressure (`router/GatewayTopicRouter.java`).
- **Event bridge with deduplication**: `GatewayEventBridge` subscribes to typed domain events on the core `EventBus`, applies event-ID dedup caching (200K max entries, 30s TTL) to prevent duplicate broadcasts during replay, then serializes payloads to JSON and publishes them to the router by mapped `GatewayTopic` (`bridge/GatewayEventBridge.java`).
- **Binary wire protocol**: `GatewayBinaryCodec` encodes frames as [1-byte topic ID | 8-byte big-endian sequence | payload], supporting both control-frame detection and UTF-8 text commands like SUBSCRIBE (`protocol/GatewayBinaryCodec.java`, `protocol/GatewayTopic.java`).
- **Spring WebSocket adapter**: `GatewayWebSocketHandler` extends `BinaryWebSocketHandler`, bridges Spring session lifecycle to the transport-agnostic router, handles subscription commands (single-topic or ALL), and delegates REPLAY_CONTROL frames to an optional `GatewayReplayCommandProcessor` (`websocket/GatewayWebSocketHandler.java`).
- **Configuration via Spring Boot properties**: `GatewayProperties` exposes websocket path, session timeout, and max message size under `tradej.gateway` prefix (`config/GatewayProperties.java`).
- **Dependency direction**: gateway → core (domain events, EventBus), gateway → broker-api (InstrumentResolver), gateway → runtime-hotpath; no reverse dependencies.
