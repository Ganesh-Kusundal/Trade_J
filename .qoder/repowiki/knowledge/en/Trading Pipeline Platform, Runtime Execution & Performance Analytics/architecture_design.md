- Three sub-packages with distinct responsibilities: `platform/trade-pipeline-platform` provides immutable domain records (PipelineDefinition, PipelineSnapshot, PipelineExecution) and a catalog service backed by a PipelineStore interface; `runtime` delivers two separate execution engines — PipelineRuntimeService for HOT_PATH mode and DagPipelineRuntimeService for DAG mode — both compiling PipelineGraph definitions into executable node graphs via GraphCompiler; `analytics/trade-analytics` exposes PerformanceAnalytics and DrawdownAnalytics interfaces with Default* implementations computing Sharpe, Sortino, Calmar ratios and drawdown statistics.
- Dependency direction flows from analytics → platform → core, and runtime → multiple downstream modules (trading-execution, trading-strategy, data-feature-store, data-persistence), as shown in build.gradle files.
- The PipelineStore interface defines the persistence boundary for catalog operations (save/load/list definitions, snapshots, executions), with InMemoryPipelineStore as the default implementation.
- PipelineDefinition and PipelineExecution are Java records with compact constructors enforcing null-safety and defensive copying of collections/maps.
