- Entry points: `DuckDbEventStore` (implements `DomainEventHandler`) for relational event persistence; `ChronicleEventWal` (implements `EventWriteAheadLog`) for durable WAL; `EventSourcedOrderRepository` for OMS state reconstruction.
- Sub-packages: `chronicle` (WAL/audit via Chronicle Queue), `duckdb` (connection pooling and SQL stores), `oms` (event-sourced order repo), `replay` (historical query/replay services), `pipeline` (DuckDB-backed pipeline graph store).
- Dependency direction: persistence implementations depend on `core` domain ports (`DomainEventHandler`, `EventWriteAheadLog`, `EventBus`) and use Jackson for serialization; `build.gradle` declares dependencies on `:core`, `:pipeline-core`, Chronicle Queue, and DuckDB JDBC.
- Interface boundaries: `DuckDbEventStore` maps domain events to normalized SQL tables (`candles`, `orders`, `fills`, `fill_events`, `trade_lifecycle`); `ChronicleEventWal` serializes events as JSON records; `EventSourcedOrderRepository` maintains an in-memory event cache rebuilt from Chronicle Queue on startup.
