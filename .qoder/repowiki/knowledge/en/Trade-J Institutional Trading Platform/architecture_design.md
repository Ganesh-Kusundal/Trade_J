- **Dual Pipeline Orchestration**: The `:app` module wires two concurrent execution paths: a low-latency LMAX Disruptor ring buffer (`:runtime-disruptor`) for the hot path and a composable DAG runtime (`:core` graph types) for flexible strategy composition, both sharing the same domain event model.
- **Hexagonal Broker Abstraction**: All broker-specific logic (Dhan, Upstox, ICICI) is isolated behind `IBrokerConnection` ports in `:broker-api`, allowing the core engine to remain agnostic to external API changes or vendor-specific limitations.
- **Mode-Aware Execution**: A global `RuntimeMode` (LIVE/REPLAY/BACKTEST) injected via `RuntimeModeHolder` gates side-effects, dynamically swapping real broker adapters for simulated matching engines and virtual clocks without altering strategy or OMS logic.
- **Event Schema Governance**: Cross-module event compatibility is enforced via a versioned `DomainEvent` interface and centralized schema evolution rules, ensuring safe serialization across WebSocket, DuckDB, and Chronicle Queue boundaries.
