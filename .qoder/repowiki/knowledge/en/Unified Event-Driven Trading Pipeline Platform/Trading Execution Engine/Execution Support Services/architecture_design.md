- The module is organized into four sub-packages: `journal` (in-memory order event log), `readmodel` (CQRS read-model store projecting domain events into UI-facing views), `marketdata` (live PnL service and market depth orchestrator), and `pnl` (duplicate live PnL service).
- `OrderEventJournal` acts as an append-only event log keyed by orderId, accepting `DomainEvent` instances and storing typed `OrderEventEntry` records.
- `ReadModelStore` is the central CQRS projection engine: it consumes `DomainEvent` types (orders, trades, ticks, depth, candles, signals, PnL updates, scan results) and maintains in-memory `ConcurrentHashMap`-backed views. It supports snapshot capture/restore for replay isolation (`ReplaySnapshot`) and listener-based push notifications.
- `LivePnlService` exists in both `marketdata` and `pnl` packages with identical implementation — it computes net PnL by fetching positions from `PortfolioProvider`, resolving instrument keys via `InstrumentResolver`, and batch-fetching LTPs from `MarketDataProvider`.
- `MarketDepthOrchestrator` delegates to `WebSocketMultiplexer` for subscribing/unsubscribing to depth-20 market data feeds.
- Dependency direction: all services depend on port interfaces from `com.tradej.broker.api.port` (PortfolioProvider, MarketDataProvider, InstrumentResolver, WebSocketMultiplexer) and core domain types from `com.tradej.core.domain`.
